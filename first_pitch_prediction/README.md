# 투수의 초구 예측

KBO 투수 41명의 PTS 트래킹 데이터(2017–2020)로, 타석의 초구가 **어떤 구종으로, 어디로** 들어올지 경기 전·타석 전에 예측

## 1. 문제 정의

- **예측 대상**: 타석 첫 공의 ① 구종(9개) → ② 위치(24칸)
  - 구종: 직구·투심·싱커·커터·슬라이더·커브·체인지업·포크·너클
  - 위치: 타자 기준 24칸 = Heart 4 + Shadow 12 + Chase 8 → H/S/C 세 묶음으로도 평가
- **출력은 확률**: 1등 하나를 맞히기보다 "직구 60%, 슬라이더 25% …"처럼 분포를 맞히는 것이 목표
  - 실제로 쓸 때는 구종을 모르므로 위치는 P(칸) = Σ P(구종)·P(칸|구종)로 구종 확률을 섞어 예측 (**실전 값**)
  - 화면에는 누적 확률 80%까지의 구종을 보여 줌 (확실한 공은 1–2개, 애매한 공은 3–4개)
- **사용 가능 정보**
  - 경기 기록(이닝·아웃·주자·점수 차·투구 수·타순·앞 타석 결과 등)은 그 타석 시점까지
  - 트래킹 값(구종·구속·위치 등)은 **경기 전날까지만** (같은 날 더블헤더 1차전도 제외)
  - 데이터상 뒤에 나오는 행으로 알아낸 정보는 사용하지 않음 → 변수마다 미래 정보 검사 함수로 확인
- **평가**: 2017–2018은 과거 기록으로만, **2019로 파라미터·모델을 고르고 2020으로 확인**
  - 점수: 구종·24칸 log loss, top-k, H/S/C 정확도, 좌표 NLL·거리
  - 모델 비교는 경기 단위 부트스트랩(같은 경기 공은 독립이 아니므로 경기째로 다시 뽑음) 95% 구간으로 판정

## 2. 진행 방식

1. **베이스라인**: "투수가 경기 전날까지 하던 대로"
   - 구종 = 투수의 최근 초구 구종 비율(반감기 가중) + 타자 손, 기록이 적으면 전체 비율 쪽으로 당김
   - 위치 = 투수×구종×타자 손의 위치를 2차원 정규분포로 → 24칸 위에서 적분
2. 그 위에 **한 번에 한 가지만 바꾸고**, 2019에서 좋아지고 2020에서 나빠지지 않으면 채택
3. 단계 순서: 1단계 베이스라인 구조 다듬기 → 2단계 구종 → 3단계 위치
   - 위치 파라미터는 "실제 구종을 알 때" 기준으로 골라 구종 모델과 독립 → 구종을 바꿔도 위치는 그대로, 실전 변화 = 순수한 구종 개선

## 3. 적용

**1단계 – 베이스라인 다듬기**

| 모델 | 내용 | 효과 |
| --- | --- | --- |
| model_01 | 구종·위치 파라미터 다시 고르기 (최근 1–3경기 기록이 가장 중요) | 구종 −0.006, 24칸 −0.008 |
| model_02 | 위치 기준점을 시즌 중에도 갱신 | 24칸 −0.001 |
| model_03 | 정규분포 → 24칸 적분에 좌우·높이 공분산 반영 | 24칸 −0.022 |

**2단계 – 구종**: 베이스라인 확률을 출발점(LightGBM `init_score`)으로 두고 상황에 따른 보정만 학습

| 모델 | 내용 | 효과 (구종 log loss) |
| --- | --- | --- |
| model_05 | 이번 타석 상황 (투구 수·같은 타자 몇 번째·아웃·주자·점수 차·타순 등) | **−0.035** (2단계 이득의 약 87%) |
| model_06 | 새 시즌 첫 경기 전에 지난 시즌 기록 무게 낮추기 | −0.004 |
| model_07 | 앞 타석 초구 결과 | −0.0003 |
| model_09 | 보정 모델을 월 단위로 다시 학습 | −0.001 |

**3단계 – 위치**

| 모델 | 내용 | 효과 (24칸 log loss, 실전) |
| --- | --- | --- |
| model_11–13 | 시즌 초 무게, 다른 카운트 위치 성향, 분산을 평균과 따로 당기기 | 합계 −0.0014 |
| model_14·16 | 상황(주자·점수 차·이닝·아웃·홈/원정·타순)으로 24칸 보정, 월 단위 재학습 | −0.0038 |
| model_18 | **높이를 타자 존 비율 대신 절대 높이(cm)로** | **−0.0135** (3단계 이득의 약 70%) |
| model_20 | 정규분포 중심·퍼짐을 상황별로 이동 | −0.0008 (좌표 NLL −0.006) |

- 가장 큰 개선은 새 변수가 아니라 **처음 세운 가정을 데이터로 다시 확인한 것**이었음 (위치 높이는 타자 키에 비례한다는 가정이 틀렸음, 좌우·높이 독립 가정)

## 4. 시도했지만 제외

| 시도 | 결과 |
| --- | --- |
| 주자 신원 (1루 주자의 타순) | 구종·위치 모두 신호 없음 |
| 투수 이력 (등판 간격·역할 전환), 상대 타자 성향, 포수·구장·월 | 베이스라인이 이미 담고 있어 남는 효과 없음, 팀·구장 단위 잔차는 다음 해에 반복 안 됨 |
| 투수×상황 반응, 구종별 최근 구위·결과 | 칸 표본 부족 / 크게 나빠짐 |
| 단계적 분류 (구종 계열 → 구종, H/S/C → 24칸) | 한 번에 학습한 모델과 같거나 2020에 효과 없음 |
| 리그 최근 잔차 (달마다 직구 비율 어긋남) | 2019 신호 없음, 대부분 표본 잡음 |
| 위치: 타자 장타 비율·직전 타자 결과·투수 피로·오늘 제구 상태 | 상황 변수 위에서 남는 몫 없음 또는 나빠짐 |
| 기준점 투수 동일 가중, 단계 끝 파라미터 다시 고르기 | 차이가 잡음 수준 |
| 전체 투구(모든 카운트) 모델 블렌딩 | log loss는 −0.004 좋아졌지만 1등 정확도·macro F1이 떨어져 **보류** |
| 궤적(구속·무브먼트·회전·릴리스) 예측 | 진행했지만 프로젝트 범위에서 제외 |

- 공통 교훈
  - 2019로 여러 파라미터를 각각 고르면 2019 이득이 부풀려짐 (2020에서 거의 0) → 파라미터를 새로 고르지 않은 구조 변경이 2020에도 잘 이어짐
  - 변수 묶음의 효과는 주된 묶음을 넣은 뒤 다시 재야 함
  - 해마다 범위가 커지는 변수(누적 기록 수 등)는 학습 해에 없던 값이라 나빠짐

## 5. 결과 (2020 평가)

| 지표 | 무작위 | 베이스라인 | 최종 (model_20) |
| --- | --- | --- | --- |
| 구종 log loss | 2.20 | 1.102 | **1.056** |
| 구종 top1 / top2 | | 0.524 / 0.811 | 0.533 / 0.822 |
| 구종 macro F1 | | 0.258 | 0.355 |
| 24칸 log loss (실전) | 3.18 | 2.979 | **2.926** |
| 24칸 top3 | | 0.283 | 0.307 |
| H/S/C 정확도 (무조건 C = 0.385) | | 0.388 | 0.402 |
| 구종×칸 동시 log loss (216가지) | 5.38 | 4.042 | 3.926 |
| 좌표 평균거리 | | 32.0cm | 31.6cm |

- **구종**: 무작위 대비 log loss를 절반으로 줄였고, 누적 80%로 평균 2.4개를 보여 주면 실제 구종이 약 90% 포함되고, 구종 2개를 보여주면 약 82% 포함
- **위치**: 개선은 있지만 어려움의 대부분이 여기에 있음
  - 같은 투수·같은 구종도 공이 반경 30cm쯤 흩어지고, 이 퍼짐의 대부분은 실행 오차
  - 노린 위치를 완벽히 안다고 해도 H/S/C 정확도는 44–46% 정도가 한계로 추정
  - 좌우·높이 구분력은 대부분 구종에서 나오고, 존 안/밖 구분력은 작음
- 한계: 투수 41명 데이터라 리그 전체로 일반화되는지는 확인 필요, 구장마다 트래킹 측정 기준이 달라 위치 측정 보정 여지가 남아 있음
